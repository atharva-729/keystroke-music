Can you hear … accuracy?

A model guessed which key was pressed from the sound alone. We turned its guesses into music. Every wrong note is a key it misheard.

  • A small model learned what each of 36 MacBook keys sounds like, from a phone recording.
  • We played it typing it had never heard and it named each key.
  • Every key is a fixed note. Each phrase plays twice: what was typed, then what the model heard.
  • Same tune = right. Wrong note = a key it misheard. No stats needed to judge it.

The data

  • Public recordings from the paper: a MacBook Pro recorded by a phone 17 cm away. Source
  • 36 keys (0–9, a–z) × 25 presses each = 900 clicks. Each file is one key, so the labels are free.
  • No new recordings. Everything here is reproducible from the public data.

When the model is sure, it is almost always right

  • Over 90% sure: 48 of 49 right. Under 70% sure: 14 of 26, close to a coin flip. The model's confidence means something.
  • In practice you could keep only the guesses that are at least 70% sure: 76% of presses, and 96% of those are right, then send the rest for a second look.
  • It is not always humble: one of 6's presses was heard as 8 at 89% sure and another at 91%. The two keys sound nearly the same to it.
That is the result. Everything below is the how.

How it works

  1. Isolate: cut each key's recording into its 25 clicks using the paper authors' own isolator.
  2. Train: a compact CoAtNet-style model maps a click's sound (a mel spectrogram) to a key, using presses 1–20.
  3. Stitch: build each phrase from held-out clicks (presses 23–25), spaced 0.45–0.6 s apart, with 1 s for a space.
  4. Listen: run the same isolator on the stitched audio, as an eavesdropper would, classify each click, and turn true and guessed keys into notes.

An honest note

  • The phrases were stitched from held-out recordings, not live typing. Real fast typing overlaps presses and would score lower.
  • One MacBook, one recording session. A model like this is tuned to the device it learned from. Eshwar measured about 4–5% (near chance) on a different device.
  • The paper reports 95% with a larger model and a random split. This is a smaller model on a stricter split: it is tested on the last presses of each key, never mixed with training presses.
  • The isolator found the right number of clicks in every phrase on its own.

The note mapping (fixed, nobody picked notes by ear)

1 … 0square wave, softColumn from the left → step of C4 D4 E4 G4 A4 C5 D5 E5 G5 A5 (pentatonic, so wrong notes sound different, not ugly)

Every key has its own (instrument, pitch) pair. In "what the model heard", loudness follows confidence: gain = 0.3 + 0.7 × confidence. Both melodies use the real click times, so the rhythm matches the clicks. The music shows the model's accuracy. It says nothing musical about the keys themselves.

Reproduce

git clone https://github.com/atharva-729/keystroke-music && cd keystroke-music
python -m http.server                                   # just listen: the clicks are in data/demo.json
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install librosa numpy scipy soundfile
# optional, data/phone.npz is already in the repo; to rebuild it from the raw recordings (~640 MB):
#   git clone https://github.com/eshwarpotturi/keystroke-replication ../sources/keystroke-replication
#   git clone https://github.com/JBFH-Dev/Keystroke-Datasets ../sources/ksd
#   python scripts/isolate.py                           # 36 keys x 25 clicks -> data/phone.npz
THREADS=4 python scripts/train.py phone phone 0 150 ordered   # ~10 min on CPU -> models/phone.pt
python scripts/build_demo.py                            # -> data/demo.json
python -m http.server                                   # open http://localhost:8000
